# Proposal

## Why

The game runs on a single AWS EC2 instance (`infra/aws`). We want a second, independent deployment on Hetzner Cloud, which gives roughly 3× the CPU and RAM for less money and a fallback if the AWS stack is down. The DNS zone, the Terraform state bucket and the secrets already live in AWS, so the Hetzner deployment should run the servers on Hetzner and keep using those AWS services instead of copying them.

## What Changes

- **New Terraform root `infra/hetzner/`.** It uses the `hcloud` provider for the server and the `aws` provider for the parts that stay in AWS. It provisions:
  - a Hetzner Cloud server: ARM `cax11` on Ubuntu 24.04 by default, running Docker Compose behind Caddy, the same topology as AWS;
  - a separate Hetzner Volume for the SQLite database and Caddy's certificates, with delete protection and `prevent_destroy`;
  - a primary IPv4 and IPv6 address that are kept if the server is replaced, like the AWS Elastic IP;
  - a Hetzner Cloud Firewall that opens 80/443 to everyone and SSH only to operator CIDRs;
  - an SSH host key generated by Terraform, so operators verify the server from their first connection;
  - **in AWS:** Route 53 `A`/`AAAA` records for two separate Hetzner subdomains in the existing hosted zone (for example `investor-game-hz.utrakme.com` and `investor-game-api-hz.utrakme.com`);
  - **in AWS:** ECR repositories for the Hetzner stack's images;
  - **in AWS:** an S3 bucket for daily database backups, plus a write-only IAM user for uploads;
  - **in AWS:** remote state in the existing S3 state bucket, under its own key.
- **New deploy command `scripts/hetzner-deploy.sh`.** It has the same interface as `scripts/aws-deploy.sh` (`--tag`, `--allow-dirty`) and the same guarantees: it builds for the server's architecture, refuses a dirty tree, fails before touching the running stack if a required secret is missing, waits for health and prints the rollback tag. Instead of SSM Run Command it uses SSH. Secrets are read from SSM Parameter Store under a separate prefix (`/investor-game/hetzner-prod/`) and streamed to the server without being written to the operator's disk.
- **Daily off-site backups.** Hetzner Volumes have no snapshots, so a systemd timer on the server makes an online SQLite backup every night and uploads it to the S3 bucket. The upload key can write objects but cannot read, list or delete them. Bucket versioning and lifecycle rules keep at least 7 days of backups, and the bucket survives `terraform destroy`.
- **Small shared change.** `docker-compose.aws.yml` gets an optional image-namespace variable, which defaults to the current `investor-game`. The Hetzner stack can then reuse the same Compose file and `docker/Caddyfile` unchanged. AWS deploys behave exactly as before.
- **README.** A "Deploy to Hetzner" section covering prerequisites, the Hetzner API token, first deploy, operating, restoring from backup, tearing down and cost.

## Capabilities

### New Capabilities
- `hetzner-deployment`: Runs the game on Hetzner Cloud at its own HTTPS subdomains. It covers infrastructure as code, with DNS, secrets, the image registry and backups in AWS; HTTPS; production runtime config; secrets handling; durable data with off-site backups; deploy and rollback; and SSH-only operator access.

## Impact

- **New files:**
  - `infra/hetzner/*.tf`, `cloud-init.yaml`, `terraform.tfvars.example`, `.terraform.lock.hcl`;
  - `scripts/hetzner-deploy.sh`;
  - README section;
  - `.gitignore` entries for `infra/hetzner/`.
- **Changed files:** `docker-compose.aws.yml`, which gains `IMAGE_NAMESPACE` with a default, so AWS output is identical.
- **No application code or `Dockerfile` changes.**
- **New dependencies:**
  - Terraform providers `hetznercloud/hcloud` and `hashicorp/tls`;
  - for the operator, an `HCLOUD_TOKEN` environment variable and an SSH key pair.
- **AWS resources added by the Hetzner stack:**
  - 2 ECR repositories;
  - 1 S3 bucket;
  - 1 IAM user with a put-only policy;
  - Route 53 records in the existing zone.

  The Hetzner stack does not read or change the AWS stack's resources or state.
- **Cost:** about €5–7/month on Hetzner (cax11, 10 GB volume, IPv4) plus under $1/month in AWS (S3, ECR, Route 53 queries), plus LLM usage.
